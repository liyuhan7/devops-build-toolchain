# ADR-004：Schema 版本与兼容性管理

- 日期：2026-09-20
- 状态：提议，待配对组确认
- 依据：E2 PPT 第 11、26 页；MIGRATION.md

## Context

多个消费者共享契约，字段改名、枚举变化或严格 Schema 下新增字段都可能使另一组无法读取。仓库已有迁移说明，但 schema_version 仍固定为 1.0，需要确定冻结与后续变更规则。

## Decision

当前 1.0 视为待配对确认的 E2 初版。冻结时记录实际提交 SHA、配对组和评审证据；历史字段变化保留在 MIGRATION.md，不假定旧样例自动兼容。

冻结后，删除/改名/改语义、改变枚举或将可选字段改为必填视为破坏性变化，提升主版本。新增字段只有在旧消费者实际接受时才可视为兼容；additionalProperties=false 的对象新增可选字段也不能直接称为兼容。

每次变更同批更新 Schema、四类相关样例、interface-index、文档、迁移说明和验证。新增版本需提供对应 Schema 与版本路由；当前 1.0 的 const 不能直接接受 1.1 或 2.0。

manifest 使用独立 manifest_version，不向现有 Job 或 Artifact 注入未声明字段。当前新增读取协议保持任务 schema_version=1.0，读取约束作为语义层约定；未来实现要同时检查版本和协议。

## Alternatives

- 无版本直接覆盖：省事，但消费者无法识别字段含义变化。
- 所有对象允许任意字段：扩展容易，但会掩盖拼写错误和不一致。
- 每次文档修订升级主版本：过于频繁；无数据语义变化的勘误只记录提交。

## Consequences

双方需要同步升级并保留过渡期旧 Schema；不支持的版本应明确拒绝。schema_version 字符串和文档更新本身不代表实现已有兼容能力。

## Validation

原有版本正向样例继续通过，破坏性输入按预期拒绝。兼容性判断使用旧消费者校验新样例，不能只运行新 Schema。当前校验结果及命令应在交付记录中保留，尚未实现的版本路由留待服务阶段验证。
